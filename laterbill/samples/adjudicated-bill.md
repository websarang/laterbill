# 하다 만 일 종결반 (Laterbill) — 심사 완료본

> 이 문서는 `SKILL.md` 2단계(에이전트 심사)를 실제로 수행한 결과물입니다.
> 입력: `harvest.py --demo`가 낸 장부 6건. 스크립트는 세기만 했고,
> 아래의 판단 — 병합, 이름 붙이기, 우선순위, 탕감 — 은 에이전트가 했습니다.

---

## 심사 메모

**병합 1건.** 장부에는 `crawler`가 두 번 올라왔습니다 — 중단된 프로젝트(75턴, 연체 5일)와
말로 한 약속("파서 중복되는 부분 리팩터링은 나중에 하자", 연체 6일). 같은 사안입니다.
**같은 빚을 두 번 청구하지 않습니다.** 한 항목으로 합치고, 말로 한 약속은 그 항목의
증거로 첨부했습니다. 6건 → 5건.

**오탐 0건.** 다섯 항목 모두 실제 투자(75~338턴)와 실제 이탈이 확인됩니다. 제외한 항목 없음.

**이름 붙이기.** 폴더 이름은 사안이 아니므로, 마지막으로 남긴 말에서 실제 사안을 읽어
다시 이름 붙였습니다.

| 장부의 이름 | 청구서의 이름 |
|---|---|
| `todo-app` | 로그인 세션이 새로고침마다 풀리는 문제 |
| `portfolio-site` | 빌드가 깨진 채 배포 앞에 선 포트폴리오 |
| `blog-migration` | 이미지 경로 일괄 변경을 못 끝낸 이사 |
| `crawler` | 차단당하던 채로 멈춘 크롤러 (+ 미뤄둔 파서 리팩터링) |
| `thesis-figures` | 색각 검증을 묻다 만 논문 그림 |

**정지 신호는 상황으로만 옮겼습니다.** 장부는 "어디서 멈췄는지"까지만 알고 있고,
"왜"는 모릅니다. 아래 어디에도 동기를 추측한 문장은 없습니다.
`crawler`와 `thesis-figures`에는 신호가 붙지 않았으므로 **비운 채로 뒀습니다** —
없는 이유를 설명하려 들지 않았습니다.

## 청구 내역 (심사 반영)

### 1. 로그인 세션이 새로고침마다 풀리는 문제 — 연체 26일

- 원금 338턴 · **이자: 3번 다시 열었다가 3번 다 떠남** · 재진입 간격 5.2 → 2.6 → 2.0일
- 납부 기한: **이미 지남** — 평균 3.3일마다 돌아오던 리듬이 26일째 끊겨 있음 (+22.7일)
- 정지 신호: **인증 단계에서 정지** · **그 무렵 다른 프로젝트가 시작됨**(3일 안에 `blog-migration`)
- 심사 소견: 재진입 간격이 줄고 있었습니다(5.2→2.0일). 떠나기 직전까지 몰입도가
  **올라가던** 프로젝트입니다. 식은 게 아니라 걸린 것 — 회수 1순위.
  막힌 지점이 명확해서 다음 걸음도 명확합니다.

> 마지막으로 남긴 말 (7/20): "로그인은 되는데 새로고침하면 세션이 풀려. 어디에 저장해야 맞아?"

### 2. 빌드가 깨진 채 배포 앞에 선 포트폴리오 — 연체 9일

- 원금 216턴 · **이자: 4번 다시 열었다가 4번 다 떠남** · 재진입 간격 3.3 → 6.0 → 10.6 → 13.9일
- 납부 기한: **이미 지남** — 평균 8.4일 리듬 대비 +0.6일
- 정지 신호: **배포 직전 정지** · **간격이 점점 벌어짐**(평균 4.7일 → 12.2일) ·
  **반복해서 다시 시작함**(3회)
- 심사 소견: 이 항목만 정지 신호가 셋입니다. 간격이 벌어지는 추세와 반복된 재시작이
  겹칩니다. 남은 것은 빌드 실패 하나이고, 그 하나가 배포와 완성 사이에 서 있습니다.
  **다시 짜는 대신 지금 있는 것 중 무엇을 남길지 정하는 게** 다음 걸음입니다.

> 마지막으로 남긴 말 (8/6): "배포 직전인데 빌드가 자꾸 실패해. 어디부터 봐야 할까?"

### 3. 이미지 경로 일괄 변경을 못 끝낸 이사 — 연체 9일

- 원금 186턴 · 이자: 재진입 2회 (간격 5.3 → 4.6일)
- 납부 기한: **5일 뒤** — "이번 주까지"라고 본인이 직접 말함 (확신도 높음)
- 정지 신호: **게시 직전 정지**
- 심사 소견: 유일하게 **명시적 마감이 있는 부채**입니다. 마감을 넘기면
  연체가 아니라 위약이 됩니다. 남은 작업도 하나로 특정됩니다 — 이미지 경로 일괄 변경.

> 마지막으로 남긴 말 (8/6): "이번 주까지 옮겨야 하는데 이미지 경로는 어떻게 일괄로 바꿔? 그것만 되면 바로 게시할 거야."

### 4. 차단당하던 채로 멈춘 크롤러 — 연체 5일 (병합 항목)

- 원금 76턴 · **이자: 4번 다시 열었다가 4번 다 떠남** (간격 3.4 → 3.4 → 2.8 → 1.1일)
- 첨부 증거: 말로 한 약속 1건 — "파서 중복되는 부분 리팩터링은 나중에 하자" (8/9)
- 납부 기한: **이미 지남** — 평균 2.7일 리듬 대비 +2.3일
- 정지 신호: **없음** (장부에 근거가 없어 비워 둡니다)
- 심사 소견: 재진입 4회는 이 장부에서 최다 타이입니다. 76턴짜리 프로젝트에 4번
  돌아왔다는 건 버리지 못하고 있다는 뜻입니다. 다만 마지막 말이 "차단당하는 것 같은데"인 점 —
  대상 사이트의 정책 확인이 먼저입니다. 기술 부채 이전에 경계 문제일 수 있습니다.

### 5. 색각 검증을 묻다 만 논문 그림 — 연체 71일 · **탕감 권고**

- 원금 98턴 · 이자: 재진입 1회
- 납부 기한: **만기 없음** — 71일간 돌아오지 않았습니다. 예측이 아니라 결정이 필요합니다.
- 정지 신호: **없음**
- 심사 소견: 되살리라고 권하지 않습니다. 두 달이 넘었으면 그건 미루는 게 아니라
  이미 끝난 일입니다. 필요해지면 그때 다시 시작하는 편이 쌉니다 — 98턴 중
  다시 쓸 수 있는 맥락은 이미 거의 증발했습니다. **정식 탕감을 권합니다. 실패가 아니라 종결입니다.**

| 순위 | 항목 | 근거 |
|---|---|---|
| 1 | 로그인 세션 문제 | 원금 최대(338턴) + 몰입도가 오르다 끊김 + 막힌 지점이 특정됨 |
| 2 | 이미지 경로 이사 | 유일한 명시적 마감("이번 주까지") — 5일 남음 |
| 3 | 포트폴리오 배포 | 남은 게 빌드 하나 + 간격이 벌어지는 중이라 지금이 마지막 기회 |

크롤러는 4위입니다. 재진입 4회로 애착은 가장 크지만, 다음 걸음이 기술이 아니라
**대상 사이트 정책 확인**이라 오늘 30분으로 끝나지 않습니다.

## 상환을 고르면 일어나는 일 — 1번 항목 예시

**멈춘 지점:** 로그인 성공 → 새로고침 시 세션 소실. 저장 위치를 묻던 중 중단.

| 안 | 지금 바로 할 일 | 여기까지 되면 끝 | 시간 | 장단점 |
|---|---|---|---:|---|
| A 빠른 진전 | 새로고침 전후의 세션 저장 상태를 한 번 재현 | 소실되는 값과 다음 확인 지점이 기록됨 | 30분 | 가장 빠르지만 구현은 남을 수 있음 |
| B 장애물 해소 ★ | 세션 저장 후보와 필요한 서버 설정을 분리 | 선택에 필요한 보안·환경 입력이 한 목록으로 정리됨 | 60분 | 즉시 화면 변화는 작지만 같은 지점의 재발을 줄임 |
| C 완결 우선 | 기존 인증 테스트를 확인하고 세션 유지 완료 조건까지 닫기 | 새로고침 후 로그인 유지 테스트가 통과하거나 차단 요소가 기록됨 | 120분 | 가장 완결성이 높지만 집중 범위가 큼 |

### B안 선택 시 상세계획

1. **인증 설정 영역** — 현재 세션이 어디에 저장되는지 확인한다.  
   여기까지 되면 끝: 클라이언트·서버 중 소실 지점이 특정됨.
2. **세션 정책 영역** — `localStorage`와 `httpOnly` 쿠키 중 현재 위협 모델과 서버 구성이
   요구하는 방식을 결정한다.  
   여기까지 되면 끝: 선택과 필요한 설정이 한 문장으로 기록됨.
3. **검증 영역** — 새로고침 후 로그인 유지 조건을 기존 테스트 또는 재현 절차로 확인한다.  
   여기까지 되면 끝: 통과 결과 또는 재현 가능한 차단 요소가 남음.

**분납이면:** 첫 작업 하나만 30분 동안 수행합니다. **탕감이면:** 실행 작업은 만들지 않고
정식 종결 사유만 기록합니다.

### 자가개선 루프

- 관찰된 패턴: 인증 단계에서 마지막 대화가 열린 채 종료됨
- 가드레일: 기능 구현 전에 저장 위치·권한·완료 조건을 체크리스트로 고정
- 점검 시점: 첫 작업 완료 직후와 다음 세션 종료 전
- 개선 판정: 새로고침 후 세션 유지 검증 결과와 장부 상태가 기록됨
- 상환 결과: 사용자 승인 후 `repaid`, `partial`, `blocked` 중 하나로 갱신
