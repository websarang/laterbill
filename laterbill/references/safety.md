# 경계 규칙

이 스킬은 사람이 남긴 가장 사적인 흔적 중 하나 — 무엇을 하다 그만뒀는지 — 를 다룬다.
그래서 경계를 기능보다 먼저 정한다.

## 1. 읽기 전용

`harvest.py`는 세션 기록과 git 상태를 **읽기만** 한다. 쓰기·이동·삭제 호출이 없다.
`--git` 옵션은 `git status --porcelain` 만 실행하며 작업 트리를 건드리지 않는다.

청구서 파일조차 사용자가 요청하기 전에는 만들지 않는다. 기본 출력은 stdout이다.

예외는 `install.py --install` 하나뿐이며, 그것도 스킬 디렉토리 안에만 쓴다.
기본 실행(`install.py`)은 진단만 하고 아무것도 바꾸지 않는다.

## 2. 로컬 전용

네트워크 호출이 없다. 청구서 내용은 기계 밖으로 나가지 않는다.
`selftest.py`는 소스에 네트워크 라이브러리가 import 되지 않았음을 직접 확인한다 —
문서의 약속이 아니라 코드가 근거다.

사용자가 공유·게시·전송을 요청하면, **무엇이 나가는지 먼저 보여주고** 확인을 받는다.
청구서에는 프로젝트 이름과 미완의 작업이 담긴다 — 회사 기밀이나 계약 정보일 수 있다.

## 3. 개인정보 마스킹

인용문은 `REDACTIONS`를 통과한 뒤에만 청구서에 들어간다.

| 대상 | 치환 |
|---|---|
| 이메일 주소 | `<email>` |
| API 키·토큰 (`sk-`, `ghp_`, `xoxb-` 등) | `<token>` |
| `password=`, `secret:`, `api_key=` 형태 | `<secret>` |
| 32자 이상 16진 문자열 | `<hash>` |
| 주민등록번호 형태 | `<id-number>` |
| 전화번호 형태 | `<phone>` |
| 홈 디렉토리 경로 | `<home>` |
| URL | `<url>` |

마스킹을 우회하지 않는다. 원문이 필요하다는 요청이 와도, 사용자가 자기 기록을
직접 여는 것이 맞다고 안내한다.

## 3-1. 공유용 익명화

마스킹은 비밀을 가리지만 신원까지 가리지는 않는다. 프로젝트 이름과 미완의 작업
목록만으로도 그 사람이 무엇을 하고 있는지 드러난다.

청구서를 남에게 보여줘야 할 때는 `--anonymize`를 쓴다. 프로젝트 이름은
`프로젝트 A`, `프로젝트 B`로 바뀌고 인용문은 `(인용문 비공개 — 열린 질문 1건)`처럼
성격만 남는다. 원금·연체·이자·재진입 간격 같은 **수치는 전부 실측값 그대로** 남는다.

정지 신호가 다른 프로젝트를 지목하는 경우(`new_project_nearby`)에도 그 이름을
별칭으로 바꾼다. 관찰은 남기고 신원만 지운다.

사용자가 청구서를 공유·게시하려는 낌새가 보이면 먼저 이 옵션을 권한다.

## 4. 심판하지 않는다

이 청구서는 사람을 평가하지 않는다. 장부를 보여줄 뿐이다.

- "왜 안 했냐"고 묻지 않는다.
- 게으르다·의지가 약하다는 함의를 만들지 않는다.
- 미완의 개수를 성격의 증거로 쓰지 않는다.
- 사용자가 자책하는 반응을 보이면 즉시 **탕감** 쪽으로 안내한다.

미루는 데에는 대개 이유가 있었다. 장부는 그 이유를 모른다.

### 4-1. 정지 신호의 경계

`stall_signals`는 이 규칙이 가장 깨지기 쉬운 지점이라 따로 못을 박는다.

신호는 **어디서 멈췄는지**만 말한다. **왜 멈췄는지는 말하지 않는다.**

| 쓸 수 있는 말 | 쓸 수 없는 말 |
|---|---|
| "배포 이야기 중에 기록이 끊깁니다" | "배포가 무서웠던 것 같습니다" |
| "인증 단계에서 마지막 대화가 멈춥니다" | "어려운 부분을 회피하셨네요" |
| "그 무렵 다른 프로젝트가 시작됐습니다" | "새것에 정신이 팔리셨군요" |
| "간격이 점점 벌어졌습니다" | "관심이 식으셨네요" |

오른쪽 열은 전부 **기록에 없는 정보**다. 마음은 기록되지 않는다. 추측을 사실처럼
적는 것은 이 스킬의 "지어내지 않는다" 원칙 위반이기도 하다.

신호는 또한 **강제되지 않는다.** 근거가 없는 항목은 신호 없이 그대로 둔다.
모든 항목에 라벨이 붙어 있다면 그건 탐지가 아니라 배정이다.

`stall_patterns`(여러 건에서 반복되는 신호)도 마찬가지다. "당신은 늘 ~하는 사람"이
아니라 "이 지점에서 여러 번 멈췄습니다"까지만 말한다.

## 5. 지어내지 않는다

- 근거가 없으면 납부 기한을 비운다. `no_basis`를 그럴듯한 날짜로 바꾸지 않는다.
- `insufficient_data` / `no_debt` 판정이면 청구서를 만들지 않고 그 사실을 그대로 전한다.
- 원금·연체·이자는 전부 실측값이다. 반올림 이상의 가공을 하지 않는다.

## 6. 민감한 항목

인용문에 건강·가족·금전·고용처럼 사적인 사안이 잡히면 `sensitive_topics`에
표시된다. 그런 항목은 **원문과 상환안을 기본적으로 숨기고 사용자에게 먼저 물어본다.**

수집기는 원문을 로컬 장부에 보존하지만 렌더러는 `sensitive_approved`가 참인 항목만
보여준다. 승인은 해당 `item_id` 하나에만 적용한다. 뺄지 말지는 사용자가 정할 일이고,
진짜 부채를 말없이 삭제하는 것도 그 나름의 부정직이기 때문이다.

묻는 방식도 조심한다. 내용을 다시 읊지 말고 "사적인 사안이 하나 잡혔는데 청구서에
넣을까요?"까지만 묻는다. 미완의 일 중에는 미루는 게 옳았던 일도 있다.

공유용 `--anonymize`에서는 이 표시 자체를 지운다. "이 사람에게 건강 관련 미완의
일이 있다"는 사실만으로도 이미 사적인 정보이기 때문이다.

## 7. 외부 행동의 경계

이 스킬은 스스로 어떤 외부 행동도 하지 않는다. 알림을 보내지 않고, 일정을 잡지 않고,
이슈를 만들지 않고, 파일을 정리하지 않는다.

사용자가 "상환"을 선택하면 프로젝트 안내 문서, Git 상태, 관련 파일, 검증 설정을
**읽기 전용으로 점검**하고 A·B·C 상환안과 선택안의 상세계획을 보여준다. 계획에는
작업 흐름을 개선하는 가드레일을 넣되 성격이나 동기를 진단하지 않는다.

파일 수정, 명령 실행, 배포는 상세계획을 보여준 뒤 사용자가 명시적으로 승인한 경우에만
별도 실행 단계에서 수행한다. 분납은 첫 작업 하나만, 탕감은 작업 없이 결정만 기록한다.
